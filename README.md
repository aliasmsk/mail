# Self-Hosted Mail Infrastructure

Автоматизированное развёртывание собственного почтового сервера на VPS с использованием Docker, Ansible и GitHub Actions.

В проекте собран почтовый стек на базе Postfix, Dovecot и PostgreSQL с поддержкой DKIM-подписи, TLS-сертификатов и веб-интерфейса Roundcube. Настройка сервера и развёртывание управляются через Ansible, а сборка Docker-образов и доставка изменений автоматизированы с помощью GitHub Actions.

## Основные решения

### Конфигурация и развёртывание

- Для Postfix и Dovecot используются собственные Docker-образы с включённой конфигурацией сервисов.
- Переменные окружения позволяют передавать параметры окружения без хранения конкретных значений в образах.
- Шаблоны конфигурации обрабатываются при запуске контейнеров с помощью `envsubst`.
- Ansible отвечает за настройку VPS и выполнение процедур развёртывания.

### Сборка и доставка изменений

GitHub Actions автоматизирует основные этапы CI/CD:

- проверку Ansible-конфигурации с помощью `ansible-lint`;
- сборку Docker-образов Postfix и Dovecot;
- Выгрузка образов в Docker Hub ;
- запуск развёртывания на VPS по SSH.

Каждой сборке присваивается тег с SHA коммита. Это позволяет определить исходную версию кода и выбрать нужный образ при повторном развёртывании.

### Безопасность почты

- OpenDKIM используется для подписывания исходящих писем.
- Certbot отвечает за получение TLS-сертификатов Let's Encrypt.
- SPF, DKIM и DMARC используются для проверки подлинности отправителя.
- UFW ограничивает сетевой доступ к серверу.
- Fail2ban помогает защищаться от повторяющихся неудачных попыток аутентификации.

| Компонент | Назначение |
|---|---|
| Postfix 3.8.13 | Отправка и приём почты по SMTP |
| Dovecot 2.3.21 | Доступ к почте по IMAP, LMTP и SASL-аутентификация |
| PostgreSQL 15 | Хранение виртуальных доменов, пользователей и алиасов |
| OpenDKIM | Подпись исходящих писем |
| Nginx | HTTPS и reverse-proxy |
| Roundcube | Веб-интерфейс почты |
| Certbot | Управление TLS-сертификатами |
| Docker | Контейнеризация сервисов |
| Ansible | Автоматизация настройки сервера |
| GitHub Actions | CI/CD |
| UFW / Fail2ban | Защита сервера |

## Развёртывание

### Требования

- VPS с Ubuntu Server 22.04 и публичным IP-адресом.
- Домен с доступом к управлению DNS.
- Установленный Ansible на машине, с которой выполняется развёртывание.
- Доступность необходимых почтовых портов у провайдера VPS.

### Настройка DNS

Для домена необходимо настроить следующие записи:

| Тип | Пример | Назначение |
|---|---|---|
| A | `mail.example.com → IP_VPS` | Адрес почтового сервера |
| MX | `example.com → mail.example.com` | Маршрутизация входящей почты |
| SPF | `v=spf1 ip4:IP_VPS ~all` | Разрешённые серверы отправки |
| DKIM | `mail._domainkey` | Публичный ключ подписи писем |
| DMARC | `_dmarc` | Политика проверки подлинности |
| PTR | `IP_VPS → mail.example.com` | Обратное разрешение IP-адреса |

Значения необходимо заменить на собственные. DKIM-запись формируется на основе публичного ключа OpenDKIM. SPF должен учитывать все серверы, которые отправляют почту от имени домена.

PTR-запись обычно настраивается в панели управления VPS-провайдера.

### Запуск

1. Клонировать репозиторий.
2. Указать адрес сервера в `inventory.ini`.
3. Заполнить необходимые переменные в `group_vars/all/all.yml`.
4. Настроить передачу паролей и других секретов предусмотренным проектом способом.
5. Запустить Ansible-playbook:

```bash
ansible-playbook -i inventory.ini site.yml
```

После развёртывания необходимо проверить DNS, выпуск сертификатов, доступность SMTP и IMAP, а также авторизацию в Roundcube.

## CI/CD

При отправке изменений в ветку `main` запускается GitHub Actions workflow.

1. **Lint** — проверка Ansible-конфигурации.
2. **Build and Push** — сборка собственных Docker-образов, выгрузка в Docker Hub.
4. **Deploy** — подключение к VPS по SSH и запуск Ansible-playbook.

Версионирование образов позволяет сопоставлять развёрнутую версию с исходным кодом и упрощает выбор предыдущей версии при откате.

## Что демонстрирует проект

Проект объединяет несколько задач системного администрирования и DevOps:

- развёртывание сервисов в Docker;
- управление инфраструктурой через Ansible;
- автоматизацию сборки и доставки изменений;
- настройку почтовых протоколов и DNS-аутентификации;
- работу с TLS-сертификатами и сетевой безопасностью.

Перед использованием в production необходимо отдельно проверить резервное копирование и восстановление данных, мониторинг, управление секретами, обработку почтовой очереди и сценарии восстановления после сбоя.
